## 真实模型验证（2026-10-30）

用合成的双栏论文（英文）和合成的中文论文，经真实网关跑通：连接测试、导入、中文问英文论文、设计动机（选中公式）、论文里没有答案的问题、实验分析、快捷术语解释、翻译、整体分析。推荐配置：**快速 = DeepSeek-V4-Flash-0731-W8A8，强 = MiniMax-M2.7-bf16**。

结果摘要：
- 引用全部可核实，没有出现编造的段落编号；“GPU 数量/数据集”这类论文里没有的信息，模型诚实回答“摘录中没有足够信息确认”，没有编造。
- 设计动机类回答能区分“作者明确陈述”与“AI 推断”。
- 中文论文 + 中文提问走 CJK 检索路径，答案正确且有依据。
- 首字延迟：快速模型约 1–2 秒；强模型（带思考）约 7–20 秒。

真实网关暴露并已修复的问题（均有回归测试）：
1. 网关不带 `stream` 参数时默认返回 SSE，部分模型非流式请求会一直挂住 → `complete()` 内部改为走流式再聚合。
2. 推理模型把思考过程以 `<think>…</think>` 混在正文里（可能被拆在多个数据块）→ 流式过滤。
3. 模型的引用写法多种多样（`[依据：P5]`、`【P3、P7】`、`（依据：P5）`…）→ 规范化后才能核实。
4. 整体分析：强模型把提示词里的字段说明原样抄回来 → 重写提示词，并加“过短/照抄说明”校验与一次重试，仍无效的字段明确标注而不是展示假分析。
5. 诚实的“没有信息”回答被误报为“缺少依据” → 归为中性的 `unverified`。
6. 流式解析：只按换行符（LF）切行（避免 U+2028/U+0085 切断数据帧）；无法解析的帧不再静默丢弃，而是计数、记录，并在回答上提示“内容可能不完整”。
7. 清理 AI 推断文本时不再吃掉括号里的解释文字；去掉模型加在小节末尾的 `---`。

**服务端缺陷（无法在客户端修复，已加兜底提示）：** Qwen3-235B-A22B 在公式密集的问题上稳定漏掉一段词（网关原始数据块里就缺，不是我们解析丢的），例如 `$ a_i $ $ W_t a_i $` 中间缺了半句话。已增加文本完整性检查（公式定界符不成对、两个公式紧挨着、加粗标记不成对），发现时在卡片上提示“回答文字可能有缺失，建议重新生成”。因此不推荐该模型做强模型。其余模型的稳定性：Qwen3.5-122B/35B/9B 在测试时段经常读取超时；DeepSeek-V3.1 返回 500；Qwen3-32B/8B 的思考内容会占满输出额度；Qwen3-Next-Thinking 把思考直接混在正文里。

仍未验证：Anthropic 适配器没有真实端点可测（只有模拟测试）；真实期刊论文的解析质量；多篇论文、长论文下的检索质量与成本。

## 真实论文验证（用户提供的 Nature Machine Intelligence 论文 + 92 页补充材料）

用户的真实文献暴露了合成 PDF 测不到的大量版式问题，解析器因此重写（`backend/paperdesk/parsing/`）：

| 真实版式特征 | 旧行为 | 现在 |
|---|---|---|
| 同一视觉行被 PyMuPDF 拆进多个 block（行内公式字体变化） | 段落碎成互相重叠的片段 | 以文字片段为原子，按基线重组视觉行 |
| 整宽图注/作者行 vs 双栏正文 | 整宽行被切成左右两半 | 行级判断：栏沟处文字连续则为整宽行 |
| 左右交替的页眉横幅、小型大写页脚 | 混进正文 | 行级页眉页脚检测（大小写不敏感、整行+分段键、包含关系） |
| 首字下沉（大号 “T”） | 丢字（“he network”），甚至被当成标题 | 并回右侧缩进行 |
| 行内粗体小标题（“Problem formalization.”） | 不是章节 | 识别为章节并剥离出正文 |
| 无 “Abstract” 字样的粗体通栏摘要 | 没有摘要 | 识别摘要，并生成 Abstract/正文 章节 |
| 图内标签、热力图数字、子图编号 | 当作正文段落污染检索 | 图区域检测（位图+矢量聚类），标记为 `figure_text` |
| 数学字体编码（`ð`=`(`、`¼`=`=`），分式被拆成碎片 | 公式文字零碎乱码 | 以公式编号为锚点归并分式/求和上下限，生成 `formula` 块与公式实体；安全字形还原 |
| 嵌套编号标题（I. / A. / 1.） | 全部同一层级 | 按首次出现顺序确定嵌套层级 |

结果：正文 8 页 0.5 秒、补充材料 92 页约 0.7 秒；正文章节大纲完整（Abstract / 正文 / Problem formalization / Model / Framework / Encoding / Decoding / Offline training / Online application / Flexibility / Data & Code availability / References…），补充材料大纲层级正确（III. → A. → 1. → Input）。新增 `figures`/`equations` 实体与区域截图接口（见 API.md）。基于合成 Nature 版式 PDF 的回归测试不依赖用户文件；另有两个在用户文件存在时才运行的真实文献测试。

**真实问答评估**（新解析器 + 真实网关模型，7 个问题，全部引用经后端核实）：训练数据规模（20 万张 30–50 节点图）、编码/解码机制（GraphSAGE 式 + 虚拟节点 + 外积 + MLP）、时间复杂度与批量选点、ANC 公式含义（模型能从乱码文字层还原出正确的 LaTeX）、设计动机（BA 图的度异质性）答案与原文一致；论文没有的信息（联邦学习/差分隐私）诚实回答“摘录中没有”。限制：仍是单篇论文、7 个问题的抽样评估，不是系统的评测集；个别数值性细节（如具体耗时倍数）未逐一核对。

## 已知问题

- 跨栏的选区做高亮时，矩形可能覆盖到另一栏的同一行（观察到过一次，选区同时跨两栏时）。单栏内选择正常。
- 作者识别基于首页版面启发式，作者行格式特殊时可能缺失或多出，元数据可在有 DOI 时由 Crossref 补全。
- 导入时 `parse_error` 在 `status=ready` 时可能非空，表示警告（如无文字层），不是失败。
- 契约小偏差：标注 id 实际是整数；`/api/ai/ask` 没有“引用已有卡片”字段，`@` 引用的卡片以文字附在问题后发送；Electron 桥新增了 `retryBackend()`。
- `.npmrc` 里的 `electron_mirror` 在 npm 11 会打印“Unknown project config”警告，功能目前正常，npm 下个大版本可能失效（届时改用环境变量 `ELECTRON_MIRROR`）。
- 在线数据源（Crossref/OpenAlex/arXiv）只用模拟响应测试过，没有在真实网络上跑；失败会降级为“保存题录/提示原因”。
- 下载导入的 PDF 不限制目标主机；个人本地使用场景下接受，若以后做成多用户服务需要加 SSRF 防护。

## 扫描版 PDF 的本地 OCR

- **做了什么**：
  - 没有文字层的页（文字少于 25 个字符、且被整页大图覆盖）按页判定为扫描页，混合型文档只处理扫描页。导入后论文**立即可读**，文字由后台任务 `ocr_paper` 识别，进度在任务页，可取消、可重试。
  - **本地离线**：用 `rapidocr-onnxruntime`（PP-OCR，ONNX Runtime）。页面图像不会发往云端，不需要联网下载模型（模型打包在安装包里：检测 2.4 MB + 识别 10.7 MB + 方向分类 0.6 MB ≈ 13.7 MB；连同 onnxruntime、opencv-python 等依赖，安装体积约 200 MB 量级，未逐项测量）。`pymupdf` 仍钉在 `<2`，不受影响。
  - 识别出的行转成行级 Span，**沿用现有解析**（分栏阅读顺序、段落切分、标题、图注、参考文献）；段落带 OCR 给出的行框 bbox；表中 `passages.source='ocr'`，接口 `Passage.source`、`/papers/{id}/text` 每项都带 `source`（`text` | `ocr`）。
  - 扫描页里的图没有图片对象可检测：用“密集短行聚类”找图区域（坐标轴刻度、图例、标注），区域内的文字归为“图内文字”，不混进正文、也不会被当成章节标题。行框高度抖动会造成误判标题，所以把接近本页中位数的行统一成正文字号。
  - 原子性：识别结果先全部放内存，最后在**一个事务**里整体替换这篇论文的段落/章节/图表；取消或失败时库里不留半截数据，论文说明里写明原因（“已取消 / 没有完成：…，可在任务页重试”）。没有识别到任何文字时如实说明。
  - 导入对话框的提示：导入完成后弹出“这是扫描版，正在识别文字（共 N 页，约每页 10 秒，不会上传到云端）…识别出的文字可能有错误，请以原文为准”。导入结果 `items[]` 新增 `ocr_job_id`、`ocr_pages`。本机没有安装 OCR 组件时，导入说明里如实写明“无法识别文字”，不创建任务。
- **测试**：`tests/test_ocr.py` 8 项（扫描页检测的正反例、OCR 行进入解析器、导入→后台任务→可检索、取消和引擎失败都不留半截数据、识别为空的说明、未安装组件的提示、真实 RapidOCR 对渲染成位图的已知文字的冒烟测试）；`pdfgen.build_scanned_text` 生成“纯图片、文字已知”的扫描样本。
- **真实样本实测**（把 Recovery 里那篇 2.3 MB 正文渲染成 150 dpi 纯图片 PDF，8 页）：词级召回 95.7%、词精度 92.9%（以原文字层的全部段落为真值）；平均每页约 13 秒（CPU）、8 页约 105 秒；渲染分辨率 110–150 dpi 最好，更高并不更准。
- **没做到 / 已知限制**：
  - 扫描页没有粗体信息，**章节小标题（与正文同字号的粗体）识别不出来**：实测原文 18 个章节只剩 摘要/正文 等少数几个，目录不完整；也可能把偶发的大号图内标签误当成标题。
  - 公式、上下标、希腊字母识别很差（OCR 面向普通文字）；行内数学不可靠，公式识别请走“公式截图识别”。
  - 速度：每页约 10–13 秒，92 页的文档要二十分钟左右；目前顺序识别，没有做多页并行。
  - 页面有旋转时的坐标换算写了反旋转，但没有用真实旋转的扫描件验证。
  - 前端只做了导入提示和类型；阅读器里“这段是 OCR 识别的，可能有误”的标记需要在文字阅读器里读取 `source` 来显示（不在本次范围）。
  - 没有在 Electron 真机里验证；没有云端视觉模型兜底（本地 OCR 装得上，所以没有做需要用户同意才发图的云端方案）。

## 复现：隔离执行器（Docker）与按目录讲解代码

- **做了什么**：复现计划里有命令的步骤可以“在隔离环境中运行”：点按钮 → 确认框（命令、镜像、是否联网、内存/CPU/进程/时长上限，上限只能调小）→ 确认后作为可取消的后台任务 `repro_exec` 在 Docker 容器里运行，日志实时回传，取消和超时都会 `docker kill` + `docker rm -f`。后端 `repro/executor.py`，接口见 [API-code.md](API-code.md)“隔离运行”；前端 `features/code/repro/ExecPanel.tsx`。
- **安全**：容器默认无网络（单步勾选才联网并记入日志）、代码只读、独立可写目录、非 root、`--cap-drop ALL`、只读根文件系统、不用 `--privileged`、不挂 docker.sock、不传任何密钥；docker 用完整路径调用；命令与确认框展示的不一致就拒绝；同一仓库一次只跑一个。
- **镜像**：不自动下载。先查本机 `docker images`，没有就在确认框写明“需要拉取镜像 xxx，约多大”，用户点“同意并拉取镜像”后才拉取（独立任务，可取消）。
- **结果可追溯**：只把真的从输出文件（csv/json）或日志里单独成行的 `名称: 数值` 解析出来的数当结果，每个数带来源（哪次运行、哪个文件或日志第几行），导入后对比表和报告都显示来源。失败、超时、取消如实显示原因，且不能导入为结果。
- **代码讲解补的缺口**：原来只能解释文件、函数、类、行范围，没有“模块”。新增 `module`：文件树里目录行悬停出现解释按钮，发给模型的是该目录最重要的几个文件的开头，证据仍逐条回查真实文件与行号。阅读器“更多”菜单里“代码工作区”在论文原文含代码链接时提示“论文里有代码链接”。路径本来就通：论文页（更多菜单）或文献库菜单 → 代码工作区 → 获取向导（自动列出论文里的链接）→ 静态分析 → 文件树/大纲 → AI 解释，证据点击跳到代码行。

## 端到端测试发现的缺陷修复

真实网关端到端测试（scratchpad\e2e_all.py）发现并修复了下面这些问题；每项都有后端测试，后端全量与前端 typecheck、vitest 通过。

1. **搜索“0 条”**：不是项目缺陷。搜索与推荐接口的结果字段叫 `results`，测试脚本读成了 `items`。项目侧加了兜底：相关性闸门把全部候选都过滤掉时，退回按综合评分的前几条并写明原因（`test_discovery.py` 新增 2 项）。
2. **个性化推荐“失败”**：同上（字段名）。重排失败本来就会回退到不重排的结果（`llm_rerank` 捕获 `LLMError`）。
3. **强模型 503 无回退**：`LLMProvider` 增加 `fallbacks` 与 `fallback_events`。强模型重试耗尽后仍遇到 5xx / 超时 / 连接错误、且还没输出任何内容时，自动改用快速模型再试一次，并如实告知：流式 `stage` 事件、卡片 `verification.notes`、论文分析的 `verification.notes`、比较结果的 `warnings`、知识整理结果的 `notes`、代码解释卡片的 `verification.notes`；用量记在实际回答的模型名下。认证失败等不可重试错误不回退；已经输出过内容之后失败也不回退（避免回答前后来自两个模型）；连接测试不使用回退，如实报告强模型状态。（`test_model_fallback.py` 6 项）
4. **任务取消太慢**：`JobContext.run_async` 代替 `asyncio.run` 运行所有异步任务处理器（分析、嵌入、全文翻译、代码、比较、研究提示、知识整理、补充材料、思维导图、视觉批量等 13 处）：取消一发出就中断正在进行的网关请求并抛出 `JobCancelled`，3 秒内变为 `cancelled`；另提供 `ctx.cancellable(awaitable)`。（`test_job_cancel.py` 4 项，网关故意拖 30 秒）
5. **复现评估“已找到”无证据**：`_item` 增加硬性规则，`found`/`risk` 没有证据就降为 `uncertain`。`languages`（每种主要语言给一个真实源码文件）、`framework_versions`（依赖文件里的那一行）、`consistency`（论文原句 + 代码位置）补上了真实证据；来源、提交日期、扫描范围这类不对应某一行代码的风险，新增“仓库级事实”证据类型 `{"type":"repo","quote"}`（界面显示为“仓库记录：…”，不可跳转）；`risk:unpinned` 给出没有固定版本的依赖行。（`test_repro.py` 新增 2 项）
6. **补充材料授权接口**：`POST /papers/{id}/supplements/authorization` 同时接受文档写法 `granted` 和旧写法 `allow`（同时给且冲突返回 400），可选 `ttl_seconds`（60 到 604800 秒，缺省 8 小时），未知字段返回 400。“解释数据集”接口以实现为准修正文档：它是后台任务，不是 SSE。
7. **“仅保存元数据”**：`POST /import/doi` 与 `/import/url` 新增 `metadata_only`（默认 false 保持原行为）。为 true 时不发任何 PDF 下载请求，条目状态 `metadata_only`，之后可用 `attach_pdf` 补上；直链 PDF 没有题录，如实失败。发现页论文卡片新增“仅保存元数据”按钮。（`test_api_library.py` 新增 3 项）
8. **H4（5 万 vs 50 万）**：合成仓库里确有 `MEMORY_SIZE = 500000`，断言本身没错；失败是因为当时强模型 503，一致性检查退化成只靠规则抽取（报告 `ai_used=False`）。第 3 项的回退让这条路径可以用快速模型完成；脚本里在 `ai_used=False` 时改为“跳过”而不是误报失败。

**没验证**：以上修复都只用假模型和模拟网络测过，没在真实网关上跑；强模型回退的“流式过程中就告知”只在后端事件里有（`stage`），界面是否显示由现有的阶段提示负责；其它使用强模型的后台任务（代码关联、补充材料分析、复现评估等）在回退时只写服务端日志，没有逐个在结果里展示说明。

## 重新解析已导入的论文（解析版本、用户数据重映射、撤销）

- **为什么：** 图内数据归类（`parsing/datablocks.py`）、表格还原、扫描页 OCR、更准的图区域外框等解析改进只对新导入的论文生效，库里的旧论文（包括截图里 Fig.5 数字堆砌的那篇）不会受益，也没有入口。
- **做了什么：**
  - **解析版本：** `parsing.pdf_parser.PARSER_VERSION = 2`，导入/重新解析时记入 `papers.parser_version`（旧库默认 1）；列表与详情带 `parser_version` / `parser_outdated`；文库行有一行安静的“有新版解析，可重新解析”（点一下就重新解析，不会冒泡成打开论文），列表顶部在有旧版论文时给一条提示（“全部重新解析…”）；行菜单、批量条（“重新解析…”）、阅读器“更多”菜单都有入口，都先弹出说明与确认。没有 PDF 的论文与补充材料子论文不显示入口。
  - **重新解析（`library/reparse.py`，任务 `reparse_paper`，可取消）：** 解析与 OCR 在事务外，**一个事务里原子替换**段落、章节、页面尺寸、图、公式，并重映射用户数据；失败或取消时旧数据完全不变（测试：事务中途抛错、解析失败、取消、新解析段落数少得可疑，旧数据逐字节不变）。开始前取消该论文上其它后台任务；完成后自动重建语义索引、按“自动分析”设置启动公式与表格识别；补充材料子论文随主论文一起重新解析；处理进度在重新解析期间显示“重新解析中”。
  - **用户数据不丢：** 笔记（先按引用原文、再按位置框 + 文本相似度映射；对不上的**保留原文引用与页码**，标为“位置已失效”，阅读器笔记里有标记）、AI 卡片证据、整体分析、思维导图、研究提示、知识条目/候选、复现评估与目标、论文↔代码关联、阅读位置都重映射；公式 LaTeX / 图理解 / 表格识别缓存按位置框重新关联到新的 id（对不上的丢弃并重新识别）；翻译缓存按文本哈希保留。详见 [API.md](API.md#重新解析已导入的论文)。
  - **撤销：** 事务内先把旧数据与“被改写之前的值”存成快照（`reparse_backup`，保留最近一次，7 天），`POST /papers/{id}/reparse/undo` 原样恢复（含原 id）；重新解析之后新建的笔记按“新→旧”映射挪回。完成后提示“已重新解析，可撤销”，阅读器“更多”里有“撤销上次重新解析”。
- **测试：** 后端 `tests/test_reparse.py` 15 项（版本标记、无 PDF 拒绝、替换与重映射的各类数据、公式与图缓存重新关联、事务内失败/解析失败/可疑结果/取消、撤销、7 天失效、删除论文清理快照、重新解析期间的处理进度、补充材料一起重新解析、扫描版走 OCR、映射函数的拆分/合并/缺失、**真实文章冒烟：Fig.5 的数字段落归为图内文字、笔记跟着图注挪到新序号、图内数据表重建出 ≥ 6 张子表**）；前端 `reparseModel.test.ts`、`PaperItems.reparse.test.tsx`。
- **没验证 / 限制：**
  - 没有视觉确认（浏览器窗格隐藏）；没在 Electron 里看。
  - 映射靠“同页位置框 + 文本相似度”，新解析把一个段落大幅拆分/合并后，个别用户数据可能映射到相邻段落（笔记优先按引用原文找，比其它数据更稳）；对比较结果（`comparisons`）、知识关系（`kb_relations`）里的证据序号没有重映射（它们跨论文引用，混在一起不好判断归属）。
  - 重新解析前只保留最近一次快照；撤销之后再重新解析会得到新的快照。
  - 补充材料的快照是各自独立的：撤销要在每篇上分别操作（目前界面只在主论文上提供撤销，补充材料需要重新解析一次才会再有快照）。
  - 后端全量测试在机器负载高时有两个已知的偶发时序失败（`test_materials` 远程下载审批、`test_folders_filters` 列表性能），单独重跑通过。
