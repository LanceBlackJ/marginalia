# 在你自己的 WSL2 / Docker / 远程机器上运行复现计划

Marginalia **不会在本机运行任何代码**。复现的流程是：在 Marginalia 里评估并批准计划 → 导出 → 到你自己的隔离环境里手动运行 → 把结果带回 Marginalia 对比。

## 1. 先在 Marginalia 里准备

1. 打开论文的代码工作区 → “复现”标签 → `1 · 可行性评估`，生成评估，通读“风险与缺口”（没找到数据、需要编译、需要 GPU 等）。
2. `2 · 复现计划` → 生成计划。逐步阅读命令，**不理解的命令不要批准**。需要改的直接在步骤里编辑（改了命令，之前的批准会作废，要重新批准）。
3. 点“导出说明 (.md)”得到带批准状态与记录的说明；点“导出脚本 (.sh)”得到脚本：**只有“已批准”步骤的命令是启用的，其余以注释保留**。

## 2. 选一个隔离环境

| 环境 | 适合 | 提示 |
|---|---|---|
| WSL2（Windows） | 没有 GPU 或只想先试编译、跑小规模 | 管理员 PowerShell 运行 `wsl --install` 后重启；在发行版里把仓库放到 Linux 文件系统（如 `~/work`），不要放在 `/mnt/c`（慢）。GPU 需要 Windows 的 NVIDIA 驱动支持 WSL。 |
| Docker | 想要干净、可丢弃的环境 | 如果仓库带 Dockerfile，优先用它（评估里会列出基础镜像）。建议 `--network none` 运行训练（数据准备好之后），只挂载需要的目录，必要时限制 `--cpus` 与 `--memory`。GPU 需要 NVIDIA Container Toolkit。 |
| 远程机器 / 服务器 | 需要 GPU 和较长训练 | 用你自己的账号，不要把密钥或令牌写进脚本；先在小数据上试跑。 |

## 3. 运行前的检查清单

- 先读代码：确认没有你不想要的副作用（删文件、联网、写系统目录、上传数据）。
- 在**新建的目录或容器**里运行，不要用你的主工作目录。
- 版本对齐：优先使用评估里“文档里写明的版本”（如 README 中的 `tensorflow-gpu==1.14.0`），它们通常比依赖文件里没固定的版本可靠；老代码用最新版本往往跑不起来。
- 数据：评估里“数据”一栏会列出论文和代码给出的获取线索；需要注册或付费的数据由你自己获取。
- 记录环境：Python / 框架 / CUDA 版本、随机种子、代码 commit、实际运行的命令。Marginalia 的“结果对比”页有“运行环境”栏可以填。
- 保存结果：把指标整理成 CSV 或 JSON（最简单是两列 `metric,value`，可加 `std` 列），例如：

```
metric,value,std
ANC,0.352,0.004
Avg score,6.10,
```

## 4. 把结果带回 Marginalia

`3 · 结果对比`：
1. 在“论文里报告的数值”里挑选或手动填写你要复现的目标数值（可设相对容差；指标定义不同的取消勾选“可比较”）。
2. 在“我的结果”里粘贴内容或填文件路径，导入。
3. 看对比表：差值、相对误差、是否在容差内或论文报告的波动范围内。必要时手动指定“论文里的这个数值”对应“你结果里的哪个指标”。
4. 在“你的结论”里写下你自己的判断，再导出复现报告。**是否算复现成功由你自己判断，Marginalia 不会替你下结论。**

## 5. 常见差异原因（供排查，均为推测，需要你核对）

随机种子未固定；数据划分或预处理不同；框架、CUDA、cuDNN 版本不同；评估协议或指标定义不同；论文报告的是多次运行的均值而你只跑了一次；代码仓库版本晚于论文（见评估里的 commit 日期）；论文与代码的参数取值不同（见“一致性”页）。
