# 思维导图与主动研究提示

对应 V2.0 说明书里的“论文思维导图”和“主动研究辅助”。界面是黑白极简；所有内容都必须能追溯到论文原文，**没有依据的东西不会出现在图里**。

## 1. 思维导图

### 三个视角
| 视角 | 回答的问题 | 典型节点 |
|---|---|---|
| 逻辑 `logic` | 作者是怎么一步步论证的 | 问题与背景 → 现有不足（动机）→ 核心思想 → 方法要点 → 实验验证 → 结论与局限 |
| 方法 `method` | 方法由哪些部分组成、怎么运转 | 框架、模块、关键公式、流程 |
| 实验 `experiment` | 实验怎么设计、结论由什么支撑 | 数据集/设置、基线、指标、结果、消融 |

每个视角独立生成、独立保存。节点只有一层根，层级 ≤ 4，同级 ≤ 8，标题 ≤ 24 字、摘要 ≤ 80 字。

### 生成流程与保证（`backend/paperdesk/mindmap/`）
1. **检索而不是塞全文**：按视角检索相关段落（BM25 关键词检索，按“方面”分别取），再加章节大纲、已有的整体分析（只帮助理解结构，不能当依据）、图表/公式清单。最多约 2.6 万字，整分支重生成约 1.6 万字。不上传整篇 PDF。
2. **强模型输出受约束的 JSON 树**，每个节点带 `evidence_ords`（原文段落编号）、可选的 `figure_ids` / `equation_ids`。
3. **后端核实**（`tree.parse_tree`）：编号必须是发给模型的摘录编号，编造的丢弃；超长文本截断；没有任何真实依据的叶子节点整个丢弃；重复节点合并。不通过就带着具体原因让模型重写一次。核实报告（丢弃了多少处引用/节点）保存在 `verification.report`，界面会如实显示“已丢弃 N 处无效引用、M 个无依据节点”。
4. **合并保存**（`tree.merge_trees`）：**用户改过或新建的节点保留**，未改动的 AI 节点被新结果覆盖。重新生成不会吞掉你的修改；只重生成一个分支时，其它分支不受影响。

### 节点能做什么
- 点击：PDF 跳到该节点的第一处原文依据并高亮；节点详情显示摘要与全部依据（`p.页码`，悬停看原文片段）。
- 关联的图/表/公式以“图 3 · p.5”“公式 (2) · p.4”标签显示，可跳转。
- 编辑标题/摘要/类型、添加子节点/同级节点、删除、折叠/展开、搜索、导出 Markdown/JSON；拖动节点可以改父级或调整同级顺序（见下一节）。
- “让 AI 解释这个节点”：走普通的研究问答管线（证据核实、引用映射、作者原文 vs AI 推断分开），结果是一张挂在节点上的研究卡片，也出现在 Insight Flow 里；不是聊天框。

### 工作区的操作（画布）
布局：一行工具栏（视角 · 搜索 · 目录 · 展开 · 撤销/重做 · 导出 · 重新生成）；画布占满主体；左侧“目录”（大纲 + 按类型过滤）可收起，宽度 ≥ 1360 时默认打开；右侧详情**只在选中节点时出现**，不再常驻占位。
画布：同级节点严格按大纲顺序自上而下排列（不用 dagre——它为了少交叉会打乱同级顺序），父节点居中于子节点，同层不重叠，折线连接；初始缩放不低于 70% 以保证文字可读，放不下时可拖动画布、滚轮缩放，或点“适应”/双击空白处；折叠/展开后视野里没有节点时自动适应画面；选中、新增节点、详情栏开合后，被挡住的节点会自动平移到可见区域。

| 操作 | 方式 |
|---|---|
| 改名 | 双击节点或 `F2`；`Enter` 提交，`Esc` 取消 |
| 新增子节点 / 同级 | `Tab` / `Enter`（新节点自动进入改名） |
| 删除分支 | `Delete`（会确认；**无法撤销**） |
| 在节点间移动 | 方向键：← 父级，→ 第一个子节点（已折叠则先展开），↑↓ 同级 |
| 折叠 / 展开 | 空格，或点节点右缘的小方块（折叠时显示被收起的子节点数） |
| 改父级 / 调整顺序 | 把节点拖到另一个节点上：同一父节点下的同级 → 调整顺序（拖在目标上半部分放前面，下半部分放后面）；其它节点 → 成为它的最后一个子节点。目标会反色高亮；放在空白处则回到整齐的布局。不能拖根节点，也不能拖到自己的后代上；层级过深会被后端拒绝并提示 |
| 撤销 / 重做 | `Ctrl+Z` / `Ctrl+Shift+Z`（或 `Ctrl+Y`）。**只覆盖**改标题/摘要/类型和移动节点；新增和删除不在其中（删除前会确认，丢失的原文依据也无法原样恢复） |
| 展开到第 N 层 | 工具栏“展开”菜单：全部展开 / 展开到第 2、3、4 层 / 只看根节点（状态同步保存到后端） |
| 搜索 | 工具栏搜索框，`Enter` 定位下一个，`Ctrl+F` 聚焦搜索框 |
| 快捷键提示 | 工具栏键盘图标；首次打开会显示，点“不再显示”后记在本机 |

视觉：黑白，层级只靠字号、字重和框的轻重区分——根是黑块，第二层是细黑框方块，更深层是带下划线的文字，选中加粗，圆角 ≤ 2px，没有阴影和色块。

### 入口
- 阅读器右侧面板的“思维导图”标签：紧凑的可折叠树 + 点击跳转。
- 阅读器工具栏 / 文献库条目菜单的“思维导图工作区”：画布 + 大纲 + 类型筛选 + 节点详情。
- 路由 `#/mindmap/:paperId?view=logic&node=<id>`。

## 2. 主动研究提示（右侧面板“提示”标签）

后台通读论文，指出**值得读者核查**的地方。这不是“挑错工具”，提示词明确禁止为了凑数而挑毛病：论证充分的论文应当返回 `verdict = no_issues`。

| 类型 | 含义 |
|---|---|
| `weak_motivation` 动机偏弱 | 提出方法的理由在原文里不够具体 |
| `weak_support` 证据偏弱 | 结论强于所展示的实验 |
| `unexplained_param` 参数未说明 | 关键超参数/设置原文没有解释来源 |
| `overreach` 结论外推 | 结论超出实验覆盖的范围 |
| `further_reading` 延伸阅读 | 值得补读的方向（没有原文直接陈述，状态为 AI 推断） |

保证（`backend/paperdesk/insights/findings.py`）：
- 每条必须带**后端核实过**的原文依据；没有有效依据的、低置信度的、重复的一律丢弃；总数 ≤ 8。
- 核查状态只有 **待核查**（原文里具体可见，需要你对照确认）和 **AI 推断**（基于推理）。**“已核查”只能由用户在核对原文后手动标记**，AI 不会自称已核查。
- 语气克制，不对作者下断言；也**不断言用户已经掌握什么**。
- 正文里不出现内部段落编号：模型写进标题/详情/总评里的 `P46`、`[P46]`、`【P46、P47】` 会被后端换成“第 12 页”（对应不到页码的带括号编号直接去掉），“摘录里/摘录中”改写成“所引原文里/中”；可点击的依据仍在下方以 `p.N` 标签显示。思维导图节点的标题/摘要同样处理。
- 用户可以：有用 / 忽略（可恢复）/ 我已核查。忽略的提示在重新扫描后不会再冒出来。
- 论文↔代码差异、正文↔补充材料不一致保留为扩展类型（`EXTENSION_TYPES`），本版本不产出，界面上也不出现。

## 3. 接口

均需 `Authorization: Bearer <token>`。

### 思维导图
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/papers/{id}/mindmap/overview` | 各视角状态、节点数、`job_id` |
| GET | `/papers/{id}/mindmap?view=logic` | 一个视角的整棵树（节点含 `refs`、`evidence`、`child_count`、`depth` …）+ `verification` |
| POST | `/papers/{id}/mindmap/generate` | `{view: logic|method|experiment|all, branch_id?}` → `{job_id, jobs}`；后台任务 |
| GET | `/papers/{id}/mindmap/search?q=&view=` | 搜索节点 |
| GET | `/papers/{id}/mindmap/export?view=&format=markdown|json` | 导出 |
| PUT/DELETE | `/papers/{id}/mindmap/positions` | 保存/重置节点位置 |
| POST | `/papers/{id}/mindmap/collapse` | 一键折叠/展开 |
| GET/PATCH/DELETE | `/mindmap/nodes/{node_id}` | 节点详情/编辑/删除 |
| POST | `/mindmap/nodes/{node_id}/children` · `/siblings` | 添加节点 |
| POST | `/mindmap/nodes/{node_id}/explain` | SSE，事件与 `/ai/ask` 相同（meta → delta → done），结果是研究卡片 |

### 研究提示
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/papers/{id}/findings?include_ignored=` | 列表 + 扫描状态/`verdict`/`summary`/核实报告 |
| POST | `/papers/{id}/findings` | 开始扫描（后台任务）→ `{job_id}` |
| PATCH | `/papers/{id}/findings/{fid}` | `{user_state?: new|read|ignored|useful, verified?: bool}` |
| DELETE | `/papers/{id}/findings/{fid}` · `/papers/{id}/findings` | 删除一条/清空 |

## 3.1 网关暂时不可用时
强模型调用（`mindmap/llmcall.py`）先按设置里的重试次数（`max_retries`，默认 2，指数退避 0.8/1.6 秒）重试；如果仍是可重试错误（502/503/超时/限流），再各等 8 秒、20 秒重来一轮（每秒检查一次是否被取消，任务日志里会写“稍等 N 秒后再试”）。仍然失败则任务失败，界面显示“模型服务暂时不可用（HTTP 502）。”，可在任务面板一键重试。

## 4. 隐私
生成思维导图和扫描提示都会把检索出的原文片段发给云端模型，每次请求都记入“隐私日志”（发送了哪些段落、多少字）。界面在生成前明确标注“会调用云端模型”。

## 5. 验证状态
- 后端：`tests/test_mindmap.py`、`tests/test_findings.py`（假 LLM）共 51 项通过：解析与核实、编造引用丢弃、用户编辑保留、分支重生成隔离、导出、解释走研究管线、扫描去重与状态规则、不断言用户已掌握。
- 前端：类型检查、vitest 通过；用假 LLM 在浏览器里走通“阅读器右侧导图/提示标签、点击跳转、有用/已核查/忽略、工作区画布”。工作区重做后另外实测（约 1100 宽的窗口，用真实生成过的导图数据）：选中后详情栏出现并自动平移、`Tab` 新增并自动改名、重命名后 `Ctrl+Z`/`Ctrl+Shift+Z` 撤销重做、拖到同级节点上调整顺序、拖到其它分支的节点上改父级并用 `Ctrl+Z` 撤销（以上每项都用后端数据核对了结果）、“展开到第 2 层”后自动适应画面、三个视角切换。`tree.test.ts`（布局顺序/居中/不重叠、移动方案、键盘导航、展开层数）13 项。
- 真实模型：验收脚本 `real_mindmap_check.py`（真实文章 + 一篇“主张都有支撑”的合成短文，检查依据真实性、编辑保留、解释卡片、提示不硬挑毛病）由主会话持密钥运行；结果以主会话回传为准，未回传前不视为“已用真实模型验证”。

## 6. 已知限制
- 节点很多时（> 60）默认只展开到第 3 层；仍然很大的图要靠缩放、平移和“展开”菜单浏览，没有缩略图导航。
- 拖动节点只用于改结构（父级/顺序），不再保存自由摆放的位置；旧数据里保存过的位置仍会沿用，可用“展开 → 整理布局”清除。
- 撤销/重做不覆盖新增和删除；撤销栈只在当前页面内有效，切换论文或重新打开后清空。
- 用户手动添加的节点按设计没有原文依据，详情里标注“用户添加”并说明没有关联依据。
- 阅读器右侧的紧凑树只改了选中态的样式，没有新的交互；完整操作在工作区里。
- 提示的“延伸阅读”只给方向，不联网检索具体文献（联网检索在“发现论文”模块）。
- 模型输出 `<think>` 的强模型（MiniMax-M2.7）生成一个视角约 1~3 分钟。

## 补充：新增与删除的撤销
- `DELETE /api/mindmap/nodes/{id}` 的返回里多了 `snapshot`：`{parent_id, index, rows:[…被删子树的完整节点数据…]}`。
- `POST /api/mindmap/nodes/restore`（body：`{snapshot}`）原样恢复：同样的 id、内容、顺序和位置。父节点必须还在（否则 404）、节点 id 不能已存在（409）、快照必须恰好是一棵挂在原父节点下的子树（400）。
- 界面撤销栈：新增的撤销 = 删除它，重做 = 用快照恢复；删除的撤销 = 恢复，重做 = 再删一次。恢复失败时会提示原因，不假装成功，也不进入重做栈。用户手动加的节点恢复后，在重新生成时仍然保留。
