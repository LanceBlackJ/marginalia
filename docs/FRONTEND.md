# Marginalia 前端说明（Electron 外壳 + React 渲染进程）

阶段一前端实现说明。与后端只通过 [`docs/API.md`](./API.md) 对接。

## 1. 运行方式

```bash
npm install                 # 依赖（npm 已配镜像；Electron 二进制若缺失见下）
npm run backend:setup       # 创建 backend/.venv 并安装后端依赖（后端同学负责）
npm run dev                 # 开发：Electron 窗口 + 主进程自动拉起 Python 后端
npm run build               # 构建 main / preload / renderer 到 out/
npm run typecheck           # tsc（node 与 web 两个工程）
npm test                    # vitest（SSE 解析、引用解析、小节解析、PDF 布局计算）
npm run dev:web             # 仅渲染进程，在普通浏览器里调试（见 §3）
```

Electron 二进制若没下载下来：
`ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ node node_modules/electron/install.js`

## 4. 设计：黑白极简（偏离 V2.0 §2.2）

> **设计偏离说明**：V2.0 说明书 §2.2 规定了以蓝色 `#416FE1` 为强调色的配色。用户看过实现后明确要求
> “简约、黑白、有简约的美感”，因此**整套界面改为黑白极简 / 纸质编辑感，不再使用蓝色强调色**。
> 功能与结构不变，只重做视觉层；全部取值集中在 `styles/tokens.css`。

设计语言：留白、发丝线、字重与字号对比分层；不用卡片、填充色块和阴影（只有下拉菜单、浮动工具栏、弹窗允许 `0 4px 16px rgba(0,0,0,.08)`）；状态用明度/字重/下划线表达，不用颜色。

### 布局原则

- **流式铺满**：页面内容区不再限宽居中，仅保留统一 `--gutter`；超宽屏（>1800px）设 1600px 上限且**左对齐**。
  顶栏标题、页面大标题、列表左边缘落在同一条竖线上。
- **用宽度承载信息**：文献库列表是表格式行，列随容器宽度显现（容器查询）：
  标题+作者｜年份｜来源｜阅读进度｜分析｜最近打开｜收藏/更多；窄时依次收起来源、年份、最近打开、分析，
  被收起的年份/来源并入作者行，不出现横向滚动。“最近阅读”是随宽度自动 3–5 列的等宽条目（标题最多两行）。
- 搜索只有一个：顶栏全局搜索（防抖 250ms，文献库列表即时过滤）。
- 设置页：一个完整的单页（没有左侧导航、没有分组标签），由一个个可折叠的小面板组成；每个设置项为“说明 | 控件”两栏（控件列 ≤560px，左对齐），所在小块较窄时自动上下堆叠。
- Insight Flow 研究卡片 = 无边框无背景的条目，条目间一条发丝线；“AI 推断”“临时”是 12px 灰描边小标签；
  证据引用 = 灰色下划线文字 `p.3`，无法核实的为虚线下划线“无法核实”；流式生成用闪烁黑色光标块。
- 选区工具栏 = 黑色浮条 + 白色图标（悬停显示说明）；Tooltip / Toast = 黑底白字。

## 6. 已知限制 / 注意

- 发现（`features/discovery`，侧栏只有“发现”一项）：页内顶部分段切换“搜索 / 为我推荐 / 随机探索”，URL 用 `/discover?tab=search|recommend|random`（`mode` 参数已被搜索的检索模式占用）；旧路径 `/recommend`、`/random` 重定向到对应 tab；三种方式共用页面框架、论文卡片（`WorkItem`）与加载/空状态（`shared.tsx`），各自的输入和结果放在各自的 store 里，切换时保留且不重复请求，随机探索仍只在点击按钮后才推荐。多论文比较（`features/compare`）、主题知识库/研究画像/全局笔记/导出（`features/knowledge`）已实现，接口见 `docs/API-discovery.md`；尚未实现的模块（如代码执行/复现）为诚实占位（标注“阶段 N 开发中”），没有假数据。
- 公式没有 LaTeX 渲染（阶段二的公式理解里再做）；Markdown 中的公式以原文显示。
- 契约里 `/api/ai/ask` 没有“引用卡片”字段：`@` 引用的卡片以文字形式附在问题后面一并发送。
- 附件上传按钮置灰（后续版本）。窗口拖放文件导入未实现（需要主进程提供 `webUtils.getPathForFile`，契约之外）。
- 深色主题未实现；快捷键不可自定义。
- 生产打包（electron-builder）与 Python 后端内置（PyInstaller 等）未做；打包后后端路径解析已预留
  （`resources/backend/python/python.exe`）但未验证。
- **Windows 窗口遮挡**：窗口被其它应用完全遮挡时 Chromium 会把页面判为 `hidden`，`requestAnimationFrame` 停摆，
  pdf.js 渲染和流式界面更新会卡住。主进程已关闭 `CalculateNativeWinOcclusion` 并设置 `backgroundThrottling: false`。
- 开发者提示：PowerShell 5.1 读取无 BOM 的 `.ps1` 会按 ANSI 解码，脚本里避免中文。

## 文字阅读器（阅读器重做）
- 方向：提取出的文字是主要阅读界面，PDF 是次要模式；右侧面板默认收起。
- 用户已有的批注（高亮）在文字界面按“逐字匹配原文”标出，匹配不到的（跨段、连字符差异）不显示，只在 PDF 界面完整显示。
- 笔记入口：顶栏“笔记”按钮与笔记标签里的“新建笔记”（不选文字也能直接写，记在当前页）。

### 显示层整理（`features/text/textClean.ts`、`frontMatter.ts`、`textModel.ts`）
数据库里提取出的原文一个字都不改，整理只发生在显示层；阅读区顶部“显示原始提取文字”可随时关掉全部整理。规则都偏保守，拿不准就不动：
- 断词：行末连字符造成的断词只在“右半是常见词尾、或左半是 ≤3 字母前缀”时合并（connectiv- ity → connectivity）；
  well- known、node- level、Yang- Yu 这类只去空格、保留连字符。
- 引用角标：粘在词尾的 1–3 位数字（networks8、systems1,2）渲染成上标；只在该词本身在论文里独立出现过时才拆，
  缩写（ANC29）要求至少出现两次，log2/top5/resnet50 等记号和模型名不拆。
- 前置信息：“首部信息”章节的段落分成 DOI、作者（去掉单位角标和损坏符号）、单位（可展开）、日期、邮箱；“Abstract”章节单独成摘要块。
- 图注：识别 “Fig. 1 | 标题. …” 拆出标签、标题（加粗）和正文；识别不出标签就按普通段落显示。
- 跨页/换栏断开的段落：上一段末尾没有句末标点、下一段以小写字母开头才接（同一页内还要求上一段不少于 80 字，避免误接短行）；
  中间隔着标题、图注、公式时不接；“显示原始提取文字”打开时不接。
- 公式：后端 `GET/POST /api/papers/{id}/equations-latex`（见 API-vision.md）整篇批量识别；打开文字界面时先读缓存，有没识别的且没有进行中的任务
  就自动开始（每篇论文只自动开始一次，之后需用户点“重试”），任务进行中每 1.5 秒刷新，公式逐个出现。识别出的 `\tag{n}` 拆出来，编号只显示一次。
- 其它：可选“首句加粗”（默认关）、右侧“本文结构”目录（阅读区 ≥ 980px 才显示，当前章节随滚动高亮）。
- **已知限制：** 正文里夹的行内数学（变量、希腊字母）和提取时被拆开的词（如 beingdi）不处理；没有直接正文的父章节不会出现在目录里；
  批注高亮是对原文逐字匹配，整理过的文字（断词、合并）里可能匹配不到。

## 文字阅读器：表格、图、行内数学、重新翻译

- **表格**：打开文字界面时先读 `GET /papers/{id}/tables-analysis`（不调用模型）；还有没识别的表就自动 `POST` 开始（每篇论文只自动开始一次，之前的任务还在跑就接着显示进度）。
  识别好的表格在表题下面渲染成真正的表格（表头加粗并有黑色粗线、数值列右对齐、细线分隔、可横向滚动），表格主体的行文字不再单独显示（“显示原始提取文字”打开时保留）。
  与 PDF 文字层核对不上的单元格用虚线下划线标出（悬停提示）；表下有“复制为 TSV / 复制为 Markdown / 对照原图”；识别中显示“正在识别表格…”（识别前仍显示提取出的行文字），
  失败写明原因并可重试，没有 API Key / 视觉模型时顶部状态条显示可读原因和重试。顶部状态条显示“表格识别 x/y”。纯函数在 `features/text/tableModel.ts`（含测试）。
- **图**：默认就内联显示在图注上方（解析器切碎的子图已按图注合并，显示整张图），快滚到时才加载；点击放大（Esc 或点空白处关闭）。截图是本地渲染，不调用模型。
- **行内数学**：只处理高置信度写法——单个希腊字母、带下划线的下标变量（v_i、x_{ij}）、含 `|·|`/`^`/`log` 的 `O(…)` 复杂度——渲染成 KaTeX；拿不准一律原样显示；
  “显示原始提取文字”打开时关闭。规则与测试在 `features/text/inlineMath.ts`。提取阶段丢掉了下标的写法（如 `v1`）无法还原，不处理。
- **重新翻译这一段**：对照/译文模式下，每个译文段落下有一个小按钮（悬停或键盘聚焦才明显）。调用现有 `POST /ai/translate`（`force=true`，后端写回译文缓存），完成后刷新译文；失败显示后端的原因。

## 阅读体验：主题、阅读外观、并排视图、专注模式、快捷键

**主题**（`styles/tokens.css`）：白、纸色（护眼暖白）、深灰、夜间。颜色全部是 CSS 变量，主题通过 `[data-theme]` 只换这一组变量；样式文件里不再写死颜色（实心控件用 `--accent / --accent-2 / --accent-off / --on-accent`，半透明用 `color-mix(in srgb, var(--text) N%, transparent)`，遮罩用 `--scrim`）。保留的字面白色只有三处：PDF 页面、PDF 缩略图、公式/图的截图底，它们本身是白底图片，暗色主题下用滤镜处理（`data-pdf`：原样 / 降亮度 / 反色）。React Flow 的节点、连线、网格颜色也改成了主题变量。
对比度（WCAG，本机用脚本计算）：正文 ≥ 10.5:1，辅助文字 ≥ 6.1:1，主按钮 ≥ 12.9:1，危险色 ≥ 6.1:1，警告色 ≥ 5.9:1；`--text-3` 只用于装饰/禁用（约 3.3–3.6:1），不承载重要信息。

**阅读外观面板**（顶栏 Aa 按钮或快捷键 A，`features/reader/AppearancePanel.tsx`）：主题、字体（无衬线/衬线/系统）、字号 13–26px、行高、行宽（窄/中/宽/满）、段间距、两端对齐、首行缩进、加粗字重、PDF 页面处理、PDF 悬停译文。偏好保存在 `usePrefs`（本机存储），`applyAppearance` 把它们写成 `<html>` 上的 `data-*` 属性与 `--rd-*` 变量，文字阅读器只读这些变量。

**视图**：文字｜对照｜译文｜PDF｜并排（`readView`）。并排 = 左文字、右 PDF，可拖动分隔条（占比记忆）、可交换左右、可关“同步滚动”；窗口窄于 1100px 时在分栏上方提示改用单栏。联动：点文字栏的段落 → PDF 翻到该页并框出该段；点 PDF 上的一处 → 文字栏滚到最近的段落（`passageAtPoint`）；一栏翻页另一栏跟到同一页（`splitSync.ts` 防止两栏来回拉扯）。PDF 上悬停段落约 0.5 秒显示译文气泡（只读译文缓存；没有译文时给“点此翻译这一段”）。

**专注模式**（F，Esc 退出）：隐藏顶栏、左右栏，鼠标移到顶部边缘临时呼出顶栏。**快捷键**（?）：J/K 翻屏、[ ] 上下一节、/ 搜索、T 切文字/对照/译文、S 切文字/并排/PDF、F 专注、A 外观、N 笔记。**阅读进度**：阅读区顶部 2px 细线 + 右下角“百分比 · 约剩 N 分钟”。

## 阅读器收尾：侧栏、目录窄条、划词工具条、PDF 智能层、阅读位置

## 页面版式整理：设置、任务中心、知识库、比较

统一规范：页面头（标题 22px/700 + 一行说明）→ 工具行 → 内容；区块之间 32px，区块有标题（15px/600）和可选的一行说明，最重要的区块顶部 2px 黑线，其余用 1px 线；低频项折叠；列表用对齐的行式布局。

- **设置页（pages/SettingsPage.tsx）**：**单页，由小面板（折叠卡片）组成，没有二级目录**。每个面板（`SettingsPanel`，features/settings/SettingRow.tsx）一行头部：标题 + 当前状态摘要（淡色一行）+ 展开箭头，点击在原地展开、再点收起，可同时展开多个；头部是原生按钮（Enter/Space 展开，`aria-expanded`）。**默认全部折叠，唯一例外：没有保存 API Key 时“连接与模型”默认展开**。展开状态记在本机（`localStorage` 的 `pd.settings.panels`，读写都有 try/catch，存储不可用时只是不记住）；用户明确展开/收起过的面板不再被默认值覆盖。内容在面板第一次展开后才挂载，所以折叠的面板不会提前加载数据。宽度够（页面容器 ≥ 940px）时折叠的面板排成两列，展开的面板独占一整行，窄屏单列；展开只做 120ms 的高度过渡，`prefers-reduced-motion` 下关闭。面板顺序：①连接与模型（默认展开仅当无密钥；其中“高级”仍是小块内的折叠）②费用与预算（价格表、月度预算）③阅读外观 ④翻译与检索（学术搜索、知识画像）⑤用量 ⑥发送记录 ⑦隐私说明 ⑧数据与存储 ⑨快捷键 ⑩关于 ⑪危险操作（头部淡色小字，默认折叠，只在已保存密钥时出现，永远在最后）。①②同属 `AIModelSection`，共用一份草稿和保存条。**发送记录**（`PrivacySection`）：摘要是总条数与最新时间；展开后默认只列最近 5 条（一行：时间、任务类型中文名、一句话摘要、约多少字），点一行才展开详情（模型、论文、段落数、包含的内容类型）；“显示更多”每次用 `before_id` 游标再取 20 条，到底写“没有更早的了”；顶部下拉按任务类型筛选（回到第一页）；不自动轮询。旧链接 `/settings/ai`、`/settings/profile`、`/settings/api`、`/settings/privacy` 等仍可用：展开对应面板、滚动过去并让标题闪一下（`resolveSettingsTarget`；`privacy` 对应原来的“发送记录”）。
- **任务中心**：状态筛选改为带数量的标签页，“全部”视图里进行中的任务单独成区放最上面；行式列表为“任务名与说明 | 类型 | 进度或状态 | 时间”，失败的任务直接显示原因；所有任务类型都有中文名（lib/format.ts）。
- **知识库**：三栏顶部 2px 黑线；条目列表头只有“新条目”一个主按钮，重命名和删除主题收进“…”菜单；主题里的论文与关系、AI 建议的主题折叠；画像页内容区最大 880px，分区用标题加细线。
- **多论文比较**：左栏按“1 选择论文、2 比较方式、3 检查并开始”分步，历史比较在最下面。

## 发现页：单页分区（取消标签式二级目录）

“发现”是一个单页，没有“搜索 / 为我推荐 / 随机探索”这样的标签切换。侧栏只有一项“发现”，页面从上到下分四个区，区与区之间用 2px 黑线和 32px 间距隔开，每个区有自己的标题（18px/700）和一句说明：

1. **搜索**：检索框 + 主按钮“搜索”，检索模式一行，AI 重排和年份收进“高级选项”；搜索结果直接在本区下方展开。
2. **为我推荐**：输入研究方向后点“获取推荐”（得到先读的综述、领域经典、近期进展三组），或点“根据我的文献库推荐”。两种方式的结果依次展开、互不覆盖。
3. **随机探索**：主按钮“随机探索一篇”，必须点击才请求；只显示来源可确认的顶刊顶会论文（白名单约束不变）。
4. **我的收藏**：在任何结果里点星标收藏的论文（原来藏在“推荐”的子标签里）。

页面顶部有一行“跳到：搜索 · 为我推荐 · 随机探索 · 我的收藏”，只是文字链接，点击平滑滚动到对应区块，没有选中态，不是标签。比较篮只在页面底部放一份。

**旧路径**：`/recommend`、`/random` 仍重定向到 `/discover?tab=…`；`tab` 参数现在只用于旧链接——打开后直接定位到对应区块（不做滚动动画）并聚焦它的主按钮，**不点击、不发任何请求**。默认打开 `/discover` 不滚动。`/discover?q=…&mode=…&seed=…` 的深链行为不变。

**论文卡片**：四个区共用同一种卡片，CSS 网格（每列最小 340px，窄屏自动减列）、同一行等高：标题（两行截断）→ 作者（一行）→ 来源年份 + 标记（已确认顶刊/顶会、发表状态、已在文献库）→ 摘要（三行截断）→ 理由（一行）→ 操作（加入文献库 / 打开原文，右侧图标：比较篮、详情、收藏）。完整摘要、DOI、各来源在“详情”抽屉里看。

验证方式见 STATUS.md 末尾。


## 阅读字体：分块字体（Times New Roman 默认）

- **字体由“英文字体 + 中文字体”组成**，拼成 CSS font-family 栈（`lib/fontPlan.ts` 的 `buildStack`）：英文字体在前，它没有的汉字自动落到后面的中文字体，所以“英文 Times New Roman + 中文宋体”这类组合成立。最后一项是通用族（serif / sans-serif / monospace）。
- **八个内容块各自设置**：章节标题、正文、摘要、图注与表注、译文（对照/译文模式）、参考文献、论文信息（开头的标题/作者/单位）、等宽内容（表格文字、代码、未识别的公式）。每块有：英文字体、中文字体、字号倍率（0.8–1.6）、加粗开关。界面（侧栏、按钮、面板）仍用无衬线，公式用 KaTeX 自带字体，都不受影响。
- **默认值（“论文经典”）**：

| 块 | 英文 | 中文 | 加粗 | 倍率 |
|---|---|---|---|---|
| 正文 | Times New Roman | 宋体（装了思源宋体则优先） | 否 | 1 |
| 章节标题 | Times New Roman | 黑体 | 是 | 1 |
| 摘要 | Times New Roman | 宋体 | 否 | 1 |
| 图注与表注 | Times New Roman | 楷体 | 否 | 1（样式本身比正文小 10%） |
| 译文 | Times New Roman | 宋体 | 否 | 1 |
| 参考文献 | Times New Roman | 宋体 | 否 | 1（样式本身比正文小 18%） |
| 论文信息 | Times New Roman | 黑体 | 是 | 1 |
| 等宽内容 | Cascadia Mono / Consolas | 微软雅黑 | 否 | 1 |

- **预设**：论文经典、屏幕舒适（Georgia + 思源宋体/雅黑，行高改为 1.95）、无衬线（Inter + 微软雅黑）、全部统一（所有块用正文的字体，标题和论文信息保持加粗）。选预设整体套用，之后逐块微调，预设显示“自定义”（由 `matchPreset` 从当前方案推出，不另存）。
- **入口**：阅读器顶栏“Aa”阅读外观 → 字体方案（预设下拉）→“分块设置字体”（每块一行：块名、加粗、倍率 ±、英文/中文下拉、实时预览，单块“恢复默认”）→“导出 / 导入字体方案”（JSON 文本框复制粘贴，不写文件）。设置页“正文阅读”里也有预设下拉。
- **字体检测**：画布测宽法（`isFontInstalled`）：同一段混合文字用“目标字体, 通用族”和单独的通用族各量一次，三个通用族里只要有一个宽度不同就算装了（只比一个会漏检，例如中文系统的默认衬线体就是宋体）。没装的字体在下拉里灰显并写“（本机未安装）”；应用自带的 Inter 总是可用；测不了宽度（没有画布）时不拦着用户。
- **自定义**：下拉里选“自定义…”，输入任意本机字体名（逗号分隔多个备选），提示“已找到：X”或“未找到，将使用备选字体”。输入会去掉引号和危险字符，最多 6 个。
- **实现**：`applyAppearance` 把每块的 `--rd-font-<块>`、`--rd-scale-<块>`、`--rd-weight-<块>` 写到 `<html>`，样式只读变量，所以切换字体不会重排整篇、只改变量。文字阅读器里译文段落统一带 `.pd-tp-trans`（对照模式另带 `.pd-tp-tr`）。
- **偏好迁移**：旧的 `readFont` 迁移到新方案：`sans`（当年的默认值，分不出是不是用户主动选的）→ 新默认“论文经典”；`serif` → 屏幕舒适；`system` → 无衬线。有 `fontPlan` 时以它为准，旧字段不再保留。
- **测试**：`lib/fontPlan.test.ts` 23 项（栈拼装、自定义解析、预设与“自定义”判定、校正、旧偏好迁移、CSS 变量、字体检测的可注入测宽、导出导入）。
- **限制**：PDF 视图里的文字是 PDF 自带字体，不受这里的设置影响；字体名检测只能判断“本机有没有”，不能判断中文字体是否带全了所有生僻字。


## 正文引用 → 参考文献（点击、右键、摘要、AI 概括）

接口与规则见 [API-references.md](API-references.md)。代码在 `features/text/`：`refModel.ts`（纯函数：上标数字拆分、按标记文字切分、引文/BibTeX、浮层定位）、`refStore.ts`（参考文献、引用标记、查询与概括状态）、`RefMarker.tsx`（正文标记与参考文献列表条目的交互）、`RefPopover.tsx`、`RefMenu.tsx`、`RefDrawer.tsx`、`RefLayer.tsx`、`references.css`。`TextReader.tsx` 只做了最小接线：`plainPieces/renderSegs` 多一个 `refs` 参数，参考文献列表条目加交互属性，末尾挂一次 `<RefLayer />`，论文打开后后台读取参考文献与引用标记。

- **哪些能点**：只有后端 `/citations` 确认过、且能映射到参考文献的标记；上标数字按“逗号分开的每个编号各自可点、区间 14–18 是一个整体”，`[12]`、`refs 3`、作者-年份按后端给的标记文字在显示文字里查找（显示文字经过整理，找不到的不处理）。“显示原始提取文字”打开时不渲染标记。
- **点击**：贴近标记的浮层，不遮挡正文（优先下方，空间不够放上方，左右夹在视口内）；显示原文、解析出的题录、本文引用处（点击跳转）和“查看摘要 / AI 概括 / 更多”。区间标记可在浮层里切换条目。
- **右键 / 键盘**：右键、菜单键、Shift+F10 打开菜单：查看详情、读摘要、让 AI 概括、在浏览器打开 DOI/链接、加入文库（只存元数据）/ 已在库则打开、复制引文、复制 BibTeX；Tab 聚焦标记，Enter 打开浮层，Esc 关闭，菜单里上下键移动。没有链接或没有 DOI 的项灰显并写明原因。
- **详情抽屉**：原文、题录、匹配可信度（低时醒目提示“可能不是同一篇，请对照原文”）、摘要全文与来源、AI 概括（流式、标“AI 生成”与依据，没有摘要时说明并给出“去查看原文”）、本文引用处、复制/打开。查询时写明“正在查询 OpenAlex / Crossref，只发送这条参考文献的标题、作者或 DOI，不发送论文正文”。
- **参考文献列表**（正文末尾折叠的一节）里每一条也可点击/右键/键盘。对照、译文、并排视图里同样可用（同一个文字阅读器）。
- **测试**：`refModel.test.ts` 10 项（数字展开、上标拆分、按标记切分、引文与 BibTeX、浮层定位）、`RefLayer.test.tsx` 5 项（点击浮层、右键与键盘菜单、查询中说明/可信度/无摘要、低可信度与流式概括、无摘要拒绝并给出原文链接）。
- **没做**：PDF 视图里选中编号后的“查看引用”（没有可靠的编号定位，不做假按钮）；行内数学的引用不处理。

## 划词翻译 SelectTranslate 与“翻译摘要”（参考文献详情）

通用组件 `components/SelectTranslate.tsx`，任何地方都能复用（AI 对话面板也可以）。

用法：页面里挂一次 `<SelectTranslate paperId={当前论文 id} />`，再给需要的容器加属性 `data-translatable`：

```tsx
<p data-translatable>An English abstract …</p>
```

- props：`paperId: string | null | undefined`（`/ai/translate` 需要它缓存译文、记隐私日志；为空时不工作）、`disabled?: boolean`。
- 在带 `data-translatable` 的容器里选中英文 → 选区上方出现浮条（翻译、复制）；点“翻译”或按 `T` → 选区下方浮层流式显示译文（走现有 `POST /api/ai/translate`，后端按文本哈希缓存，同一段不重复发送；发送的文字记入隐私日志）。
- 汉字占多数、少于 3 字、无英文单词、超过 6000 字的选中内容不显示“翻译”（仍可复制）；选区跨出容器不处理。选区变化、点击别处、`Esc` 都会关闭。
- 失败显示可读原因和“重试”；没有 API Key 时提示去 设置 → AI 模型 填写（不给重试）。
- 组件自己的浮条/浮层带 `data-selecttranslate-ui`：其它“点外面就关”的浮层要忽略这类元素的点击，`Esc` 处理也要先让它关（参考 `RefPopover`/`RefMenu`/`RefDrawer`）。
- 纯函数在 `components/selectTranslateModel.ts`（`shouldOfferTranslate`、`selectionContainer`、`placeBar`、`placePanel`），流式调用在 `lib/translateText.ts`（`streamTranslate`）。样式 `components/selectTranslate.css`，不碰字体相关文件。
- 参考文献详情抽屉：摘要下方有“翻译摘要”按钮，中文译文显示在英文下方（左侧黑色细线），流式时有骨架，失败可重试，译文由后端按文本哈希缓存；没有可信摘要（含“与标题不相符已忽略”）时不显示按钮。`data-translatable` 已加在：抽屉的摘要、原文、题录、AI 概括、本文引用处句子，浮层的原文和引用句。
- 没有做“解释”按钮。


## 划词工具条（简化版）

选中文字后出现的小浮条只保留最常用的三个动作和一个“更多”，其余功能一个不少，都收进菜单。

| | 简化前 | 简化后 |
|---|---|---|
| 主条按钮 | 翻译、解释、总结、术语解释、分析设计动机、添加笔记、提问，公式上多一个解释公式，PDF 里再加四个高亮颜色圆点，共 8 到 13 个 | 翻译、解释、笔记、更多，共 4 个，宽度约 190px，高 32px |
| 更多菜单 | 没有 | 总结、术语解释、分析设计动机、提问、高亮、复制、在文中搜索 |
| 外观 | 黑底白图标，圆点色块 | 白底，1px 黑色细边框，2px 圆角，悬停反色，四种主题下成立 |

按选区类型调整主条：

- 中文为主的选区：没有翻译，解释排第一位，翻译补进更多菜单。
- 一个词或短语（最多三个词）：翻译排第一位，其余按钮只留图标，整条更紧凑。
- 公式上的选区：解释换成解释公式，翻译和解释补进更多菜单。
- 选中的是引用编号（如 12、[3–5]），并且对得上本文参考文献：翻译换成查看引用，点击打开参考文献详情抽屉。对不上的编号不出现这个按钮。
- 文字阅读器里的选区没有 PDF 坐标，所以更多菜单里没有高亮。

高亮：菜单里点“高亮”默认用上次的颜色，右侧四个小色块可换色，换色后会记住（存在 localStorage，存不了也不影响使用）。

键盘：Esc 先收起菜单，再关闭工具条；左右方向键在主条按钮间移动，菜单里上下方向键移动。快捷键和说明只放在 title 里。

文件：`features/reader/SelectionToolbar.tsx`（组件）、`selectionToolbarModel.ts`（按钮顺序、引用编号识别、颜色记忆，纯函数）、`selectionActions.ts`（新增复制、在文中搜索、查看引用三个动作）、`reader.css`（样式）。定位逻辑 `selectionToolbarLayout.ts` 不变。文字界面、PDF 界面和并排视图共用同一个组件。参考文献抽屉里的“选中即翻译”小浮条是独立组件，没有合并。

## AI 对话面板重排

阅读器右侧 AI 标签的排版重做，功能和数据流都没变。

- **顶部：** 只有一行，左边是“第 N 页 · 章节”，右边是“全部卡片 · N”筛选。选中的文字不再在顶部出现，只在提问框上方出现一次。`ContextBar` 单独放在 `features/reader/ContextBar.tsx`，右侧可以放当前标签的内容。
- **卡片：** 一组“问 → 答”。第一行是信息行，类型 · 页码 · 模型短名 · 时间，淡色小字，模型全名在悬停提示里。第二行是问题行，选中的文字加问题，一行截断。方框标签、大标题和常驻的底部按钮都去掉了，保存、加入笔记、复制、删除收进卡片右上角的“更多操作”，悬停或聚焦时才出现。
- **回答：** 正文 14px，行高 1.7，宽屏下一行最多约 70 个字符。展开后分节，小标题 13px、加粗、黑色，节与节之间一条发丝线。AI 推断左边一条细线，标题写明“AI 推断”，不再每条带标签。核实状态是一行小字，已核实时跟在依据后面。
- **引用标记：** 回答正文里是不带下划线的小号上标灰字，悬停才加下划线。相邻的多个引用合并成一串，重复的只留一个。
- **提问区：** 输入框默认 2 行，最多长到 6 行，@、附件和发送在输入框盒子里的底部一排，发送是黑底白箭头的小方块，禁用时变灰。快捷操作只在有选中内容时出现，和选中标签在同一行，没有选中内容时整行不占位。无选中内容时总高度约 93px。
- **划词翻译：** 面板里挂了一次 `SelectTranslate`，回答正文、详细分析、依据、AI 推断、后续问题和问题行都带 `data-translatable`，输入框和选中内容标签没有。
- 模型短名、核实状态词、信息行、问题行的拼装在 `features/insight/insightModel.ts`，是纯函数，有测试。

文件：`features/insight/{CardView,PendingCardView,Composer,InsightPanel,ChainSwitcher}.tsx`、`insight.css`、`insightModel.ts`，`features/reader/{ContextBar.tsx,RightPanel.tsx,reader.css}`，`components/CiteChip.tsx`。
