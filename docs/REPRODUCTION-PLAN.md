# 第 4 阶段：论文复现——已实现的范围与边界

> 状态：**A（评估）、B（计划与批准）、C（结果对比）、D（Docker 隔离执行器）已实现。D 只用假 docker 测过，没有在真实 Docker 里跑过，见 STATUS.md。**
> 入口：代码工作区（`/code/{paperId}`）顶部的“复现”标签，分三步：`1 · 可行性评估` → `2 · 复现计划` → `3 · 结果对比`。

## 1. 硬性边界（来自原始说明书，已用测试固定）

- **Marginalia 不会在本机直接运行任何用户代码。** 评估是静态分析，计划是文档，批准是记录，结果对比是算数；这些过程不启动子进程（测试用 `subprocess` 打桩固定）。唯一会运行代码的是 D（隔离执行器），代码只在 Docker 容器里运行，宿主机上只启动 docker 本身。
- “在隔离环境中运行”只在 Docker 服务运行时可点，每次运行都要在确认框里确认命令、镜像、是否联网和资源上限；没有 Docker 时置灰并写明原因，只能导出计划手动运行。WSL2 不用于运行。
- 任何有命令的步骤（下载、安装、编译、运行）都是“待批准”；批准记录追加式落库，并记下批准当时的命令。**批准后再改命令或目录，批准自动作废**（回到待批准，并在记录里留下“撤销”），避免“批准了 A、实际运行了 B”。
- AI 不替用户断言“复现成功/失败”：对比接口的 `verdict` 恒为 `null`，结论由用户自己写；可能的原因分“事实”（有记录依据）和“推测”（明确标注）。
- 评估里找不到的写“没找到”，证据不足写“不确定”，不给乐观结论；每条结论带证据（`文件:行` 或 论文页码+原文片段）。

## 2. 三层功能

### A. 可行性评估（`repro/assess.py`）
输入：论文 + 已分析的代码仓库。后台任务 `repro_assess`，只读静态分析结果与论文原文，输出 6 组、每项带状态（已找到 / 没找到 / 不确定 / 风险 / 提示）与证据：

| 组 | 内容 |
|---|---|
| 环境 | 语言与框架、依赖文件（固定了多少版本）、关键框架版本、**文档（README）里写明的版本**、Python 版本线索、Dockerfile / conda 环境文件、需要编译的代码（Cython/C++/CUDA）、GPU 使用线索、TensorFlow 1.x 接口 |
| 入口与命令 | 训练入口、评估入口、README 里的运行命令（含 `CUDA_VISIBLE_DEVICES=0 python train.py` 这类带环境变量的写法） |
| 数据 | 仓库自带的数据文件（`data/` 目录里的源码不算数据）、模型权重、下载线索、论文声明的数据链接、AI 从论文原文抽取的数据集名称（引文必须逐字出现在该段落里，否则丢弃） |
| 资源与规模 | 代码里的批大小/轮数/迭代数/回放容量、论文提到的硬件（没有就写“不确定”） |
| 参数 | 复用“一致性检查”的结果（不同的参数列出论文值与代码值） |
| 风险与缺口 | 代码来源未确认、版本可能晚于论文、依赖未固定、没有许可证、只有训练或只有评估、没有数据、部分文件无法解析 |

另有“工作量”粗档（低/中/高）并列出依据；注明“不是时间估计”。

### B. 复现计划与批准闸门（`repro/plan.py`）
- 由评估结果按固定模板生成（不靠模型发挥）：准备环境 → 获取数据 → 编译 → 查看参数说明 → 运行训练 → 运行评估 → 对比结果；每步带证据。命令优先取 README 里的写法。
- 步骤可编辑、可勾选“已完成”、可添加自己的步骤、可删除；有命令就必须批准。重新生成计划会覆盖编辑和批准记录，需要二次确认。
- 导出：Markdown 说明（含批准状态与记录）、shell 脚本（只启用“已批准”步骤的命令，其余以注释保留）。导出文件开头写明“Marginalia 不会在本机运行”。

### C. 结果导入与对比（`repro/results.py`）
- **目标数值**：从论文文字里按规则找候选（均值±标准差、指标词后的小数/百分数、像指标行的表格行），用户挑选并确认含义，也可手动填写；用户填写的出处原句会核对是否真在该段落里（`quote_verified`）。候选规则偏保守：引用编号（`(ANC)29`）、实例数、网络名里的数字、图内坐标轴刻度都不算。
- **导入结果**：粘贴 CSV / TSV / Markdown 表格 / JSON，或给本地文件路径（`.csv .tsv .json .txt .log .md`，≤2MB）。
- **对比**：每个目标数值自动对应到结果里同名指标（有歧义不自动对应，用户可手动指定）；给出差值、相对误差，状态为 `在容差内 / 超出容差 / 在论文报告的波动范围内 / 超出论文报告的波动范围 / 未设容差 / 没有对应指标 / 无法比较`。用户可设相对容差、可标记“指标定义不同，无法比较”。单位疑似不一致（论文是 %、你的像小数）只提示，不自动换算。
- **可能相关的线索**：事实类（记录的 commit 与评估时不同；论文与代码有参数取值不同）和推测类（没记录随机种子、数据划分/版本/评估协议差异）分开标注。
- **报告**：导出 Markdown 复现报告（环境、已批准的命令、数值对比表、线索、用户自己写的结论）。

### D. 隔离执行（Docker）
`GET /api/system/sandbox` 探测 Docker 与 WSL2；Docker 在运行则 `can_run_here=true`。执行器见 `backend/paperdesk/repro/executor.py`，接口见 [API-code.md](API-code.md)“隔离运行”：默认无网络（单步勾选才联网并记录）、代码只读挂载、独立可写工作目录、内存/CPU/进程/时长上限（只能调小）、每次确认、日志实时回传、取消和超时会真的 kill 并删除容器、不自动拉取镜像（用户同意才拉）。结果只收真的从输出文件或日志里解析出的数值，每个数带来源。**只用假 docker 测过，没有在真实 Docker 里跑过。**

## 5. 已知限制

- 评估只来自静态分析：Cython 文件无法用语法树解析，只能容错解析，结果可能不完整；“没找到”不等于“不存在”。
- 同一仓库里有多份近似拷贝（如 FINDER 的 4 个变体）时，依赖文件会各列一条。
- 目标数值候选来自论文文字层，扫描版论文、图片里的表格找不到；表格没有“列名”信息，只能靠行里的指标词和位置，含义要用户确认。
- 结果对比不做单位换算，不理解指标的方向（越大越好还是越小越好），只给差值与相对误差。
- 计划里的命令是按依赖文件类型和入口脚本路径生成的常规写法，参数需要用户对照 README 与论文设置核对。
- AI 只用于从论文里抽取数据集名称（有 API Key 时），评估与计划本身不调用模型；这一步在真实网关上的效果尚未验证（见 STATUS）。
